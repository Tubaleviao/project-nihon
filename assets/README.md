# Assets — public placeholders + private production art

Project Nihon keeps **production art private** while shipping a **fully-runnable
public clone**. This directory holds the public side of that split.

## The placeholder rule

**The public game builds and is fully playable without the private repo.**
`assets-prod/` only makes the game prettier; it never makes it work.

- Every key in `assets-prod/` has a public placeholder here at the **same key**
  (and in `manifest.json` when it is a mesh or animation). Placeholders can be
  ugly: flat colours, boxes, minimal clips. They must load with no warnings.
- The placeholder lands here **first**, or in the same change as the art.
  Never add a key to `assets-prod/` that this tree does not have.
- A placeholder has the same contract as the art it stands in for: the same
  clip names, bone names where code reads bones, and image size. Code never
  branches on which one is loaded.
- No build step, test or CI job may require the submodule. CI never checks it
  out.
- Placeholders are generated by scripts in `tools/` (`gen_placeholder.py`,
  `gen_placeholder_glb.py`, `gen_item_assets.py`, `gen_holdable_icons.py`, `gen_ui_icons.py`), so they can be rebuilt.

Every item has a model and an icon, both written by `tools/gen_item_assets.py` from the item's
`shape` in the generated item data (`godot/items/`): `models/items/<ItemId>.glb.raw` (one closed
mesh, at most 300 tris, origin at the grip, a `grip` node, +Z forward, one vertex colour per part)
and `icons/items/<ItemId>.png.raw` (32x32 RGBA, a software render of the same triangles).
Every other stack a player can hold (the 12 materials and the outputs of the creature harvest tables: hides,
meat, bones, trophies) gets an icon at the same key from `tools/gen_holdable_icons.py` (a material from its
palette colour and form, a harvest output from its kind). `tools/holdables.py` is the one list of ids and
`python3 tools/gen_holdable_icons.py --check` fails when a file is stale, missing or orphaned; a new material
or drop without a row in the generator fails the run. The public build never shows the letter glyph.
UI icons are written by `tools/gen_ui_icons.py` (32x32 RGBA, a vector DSL on a fixed palette):
`icons/ui/window/<key>.png.raw` for every `WindowDock` entry, `icons/skills/<Skill>.png.raw` for
every skill (a frame per category of `SKILL_CATEGORIES` around a symbol), and
`icons/ui/hud/hp.png.raw` plus `icons/ui/hud/<effect>.png.raw` for every status effect, and
`icons/hair/<hair>.png.raw` for every hair style of the character-creation table (Phase 180). They are
listed in `manifest.json` under `textures`; `python3 tools/gen_ui_icons.py --check` fails when a
file is stale, missing or orphaned. The private repo overrides them by key.
`models/items/shapes.lock.json` hashes each shape; `python3 tools/gen_item_assets.py --check` fails
when it or the files are stale, so rerun the generator after a fabric shape change. Ten creatures (GraywolfPack,
ForestBoar, SteppeBison, GlimmerFox, VeilStalker, RiftWarden, RidgeHawk, CinderGargoyle,
VoidSerpent, LavaSlug: `models/creatures/<Entity>.glb.raw` plus three textures each) have
public placeholders, and all 29 items (CarpenterAxe, FerritePick, FerriteShortSword, FerriteShield,
FerriteHelmet, VeilsteelLongsword, VeilsteelPick, VoiditeEdge, AethermiteBow, SkinningKnife, BoneSaw, VeilsteelChestplate, DuskfiberCloak, NoviceTunic, plus the 15 materials, consumables and stations: AethermiteDust, AethermiteShard, EnchantedAethermiteShard, AlchemyPotion, AshiteBlock, FerriteIngot, VeilsteelIngot, FieldRations, LumenfiteOrb, RefinedVoiditeShard, ThornwoodPlank, VoidRuneTablet, Hearth, Waystone, Bed) also have three
`textures/items/` sheets. Other `models/creatures/<Entity>.glb.raw` keys still work
only through a code fallback (a procedural box). The asset roadmap in
`project-nihon-assets/ROADMAP.md` adds each placeholder before the art for that key.

Character creation (Phase 180): `tools/gen_placeholder_glb.py` writes the two chibi gender bodies
`models/characters/bodies/chibi_body_{m,f}.glb.raw` (skinned to HumanoidSkeleton with every player clip),
the heads `models/characters/heads/chibi_head_{m,f}.glb.raw` and one static mesh per hair style at
`models/characters/hair/<hair>.glb.raw` (origin at the Head joint, drawn from the style's `shape` in
`fabric/gameplay/characters/creation.js`); `tools/gen_placeholder.py` writes the eyes
`textures/characters/eyes/chibi_eyes_{m,f}.png.raw`. `node tools/check_creation.js` fails when a preset part
or hair style has no placeholder or manifest entry.

Rig textures: an attached player rig is drawn with the character shader, whose three sheets are
bound by key through `AssetOverlay.load_texture`: `textures/characters/player.png.raw` (detail),
`textures/characters/player_color_mask.png.raw` (R/G/B = primary/secondary/accent) and
`textures/characters/player_channel.png.raw` (R/G/B = metal/emission/wear). The public masks are
black, so colour reduces to the character's skin index.

## The model

- **Canonical keys.** Every asset is referenced by a stable relative key (e.g.
  `textures/placeholder_character.png.raw`), resolved at runtime through
  `AssetOverlay.resolve_path()`/`AssetOverlay.load_texture()` — code never
  hardcodes `res://assets/...` or `res://_overlay/...` directly.
- **The `.raw` convention.** Every asset under `res://assets/` (and its private
  counterpart in `assets-prod/`) carries an extra trailing `.raw` suffix, e.g.
  `placeholder_character.png.raw`. Godot's import pipeline compiles any
  *recognized* extension (`.png`, `.wav`, …) into a compiled resource under
  `res://.godot/imported/...` and drops the raw bytes at the bare path
  entirely from a real export — `FileAccess`/`Image.load()` on that bare path
  fail in a shipped build even though they work fine from the editor. The
  `.raw` suffix is unrecognized by the importer, so the file is packed
  byte-for-byte and stays readable via `FileAccess.get_file_as_bytes()` in
  every context, editor or export. Read such files with
  `AssetOverlay.load_texture()` (which uses `get_file_as_bytes()` +
  `Image.load_png_from_buffer()`) — never `load()`/`Image.load()`.
- **Public placeholders.** This repo commits *ugly* placeholder files at those
  exact `.raw` paths, so a fresh `git clone` opens and runs in Godot with zero
  missing-resource errors, no private submodule required.
- **Private production art.** Real art lives in the private
  [`project-nihon-assets`](https://github.com/Tubaleviao/project-nihon-assets)
  repo, wired in as the `assets-prod/` git submodule (mirroring `assets/`'s
  layout and `.raw` convention, tracked with **Git LFS**). It also carries a
  `.gdignore`, so Godot's scanner never touches it in place.
- **The `.pck` override.** `tools/build_pck.sh` stages a plain copy of
  `assets-prod/` into a disposable pack-only project
  (`tools/pack_project/_overlay/`) and runs Godot's own exporter
  (`godot --export-pack`) over it, producing `assets.pck`. Because
  `--export-pack` cannot remap a file's path, the pack's internal paths land
  under `res://_overlay/<rel>`, not `res://assets/<rel>`. At startup the
  `AssetOverlay` autoload mounts that pack over `res://`; `resolve_path(rel)`
  then prefers `res://_overlay/<rel>` when present, falling back to the
  committed placeholder at `res://assets/<rel>` otherwise — no code change,
  no private path in code.
- **Builds.** `export_presets.cfg`'s "Linux"/"Windows Desktop" presets exclude
  both `assets-prod/*` and `_overlay/*`, and force-include `assets/*` (raw
  files aren't swept in automatically). The Steam/release build additionally
  ships `assets.pck` alongside the executable; the public/GitHub build ships
  placeholders only.
- **DLC alignment.** The pack-mount mechanism is exactly how paid DLC content
  packs will be layered later: a `.pck` is the unit of optional content.

## Meshes, animations and the manifest

`assets/manifest.json` maps canonical keys to relative paths for `textures`,
`meshes` and `animations`. `AssetOverlay.load_mesh()` /
`load_animation_library()` parse `.glb.raw` bytes with `GLTFDocument` (never
`load()`). A missing key warns and falls back to the procedural body. Real rigs
come from the private `assets-prod` submodule (`git submodule update --init
assets-prod`, requires access); without it the local avatar renders the committed
`models/player_rig.glb.raw` placeholder: a blocky humanoid skinned to the fabric
`HumanoidSkeleton` bones (same names, parents, rest positions and rest orientations as
the private rig), carrying every clip the locomotion tree looks up.
`models/placeholder_rig.glb.raw` is the older unskinned body (issue #112: it used to be
a single flat triangle, which left the player's own character invisible). It renders
only for a manifest that lists no player rig, which the public one now always does.
`models/creatures/GraywolfPack.glb.raw` is the same kind of skinned box rig on the fabric
`QuadrupedSkeleton` bones, facing -Z like the private wolf (the fabric `restPose` puts the
head at +Z; `CreatureVisuals.yaw_for_direction` reconciles the two).
The nine roster creatures reuse that wolf rig (boar, bison, fox, stalker, warden), or use a
`BirdSkeleton` box rig (hawk, gargoyle) or a `SerpentSkeleton` box rig (void serpent, slug).
Each creature entity names its family in the fabric `skeleton` field.
Each rig carries idle, walk, run, fall, land, attack and death. The game attaches these models
(`src/creature/creature_visuals.gd`): a creature within 40 m of the camera (at most 24, nearest first) is
drawn as its model with the clips driven from its AI state and speed, the rest stay boxes in the shared
pool, as does any creature whose model key is absent. Each type binds its own body sheets
`textures/creatures/<Entity>{,_color_mask,_channel}.png.raw` through the character shader.
Regenerate all of them with `python3 tools/gen_placeholder_glb.py`.

## Regenerating a placeholder

```bash
python3 tools/gen_placeholder.py   # every placeholder texture
python3 tools/gen_placeholder.py assets/textures/placeholder_character.png.raw
```

`textures/characters/player_color_mask.png.raw` and `player_channel.png.raw` are
all-black RGBA (base colour only, no channel), the same as the character shader with
no mask bound. The production pack replaces them with the player rig's masks.
`textures/characters/player.png.raw` is the rig's detail sheet: all-white RGBA, the
same as `detail_tex` unbound. Unlike `placeholder_character.png.raw`, which the
procedural capsules sample across their whole UV range, the production sheet is laid
out on the player rig's UVs. Nothing binds these three keys to the character material
yet (issue #314), so for now they only reserve the keys the private sheets override.

## Building the production pack

```bash
git submodule update --init assets-prod   # private repo — requires access
tools/build_pck.sh                        # emits assets.pck (gitignored)
```

The `assets.pck` is gitignored and must never be committed — it is built from
private art and committing it would leak that art into the public repo.

## Verifying the override works

`src/tests/test_suite.gd`'s `_test_asset_pck_round_trip_override` builds a
fixture pck with `PCKPacker`, mounts it via
`ProjectSettings.load_resource_pack()`, and asserts `AssetOverlay.resolve_path`
now serves the overlaid bytes instead of the placeholder — this is a real
mount + read-back, not just a check that the relevant constants look right.
